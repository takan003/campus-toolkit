## 一、專案概述

**數位校園GAS站** 是一套以 Google Apps Script 為基礎打造的學校校園入口網站系統，採**主系統 + 外掛模組（Plugin）** 架構設計，所有資料皆儲存於 Google 試算表。系統支援三種角色（學生、教職員、管理員），提供帳號管理、認證授權、兩階段驗證、密碼重設、Google OAuth 登入及外掛模組擴充等功能。

## 四、模組劃分

### 4.1 核心模組

| 模組 | 檔案 | 職責 |
|------|------|------|
| **全域設定** | `base.js` | 版本號、版權宣告、贊助廣告、全域變數 |
| **認證授權** | `auth.js` | Token 簽發/驗證、密碼雜湊、TOTP、Email OTP、Nonce |
| **主控制器** | `main.js` | 路由分派、登入邏輯、帳號 CRUD、忘記/重設密碼、OAuth 回調、模組安裝 |
| **共用工具** | `utils.js` | 試算表查詢（key-value / column）、成員名冊定位、活動紀錄、模組清單、訊息頁面渲染 |

### 4.2 前端頁面

| 頁面 | 檔案 | 對應角色 |
|------|------|----------|
| 登入 | `index.html` | 公開 |
| 學生入口 | `student.html` | student |
| 教職員入口 | `staff.html` | staff |
| 管理員入口 | `admin.html` | admin |
| 帳號設定 | `account.html` | 全部（須登入） |
| 模組管理 | `admin_modules.html` | admin |
| Email OTP | `email_otp.html` | 全部（登入流程中） |
| TOTP 驗證 | `totp.html` | 全部（登入流程中） |
| 忘記密碼 | `forgot_password.html` | 公開 |
| 重設密碼 | `reset_password.html` | 公開（須有效 token） |
| 閒置逾時 | `idle_timeout.html` | 全部（嵌入各入口頁） |

### 4.3 外掛模組架構（以「自主學習」為例）

| 檔案 | 職責 |
|------|------|
| `main.js` | `doGet` 驗證 Module Token 後渲染首頁；`doPost` 處理安裝活化（`page=install`） |
| `auth.js` | 僅含 Token 驗證（`sessionVerify`），驗證主系統簽發的 JSON payload token |
| `utils.js` | 工具函式（日期格式化、試算表讀取、訊息頁面） |
| `base.js` | 版本號、版權宣告 |

**模組認證流程**：
```
主系統 _signModuleUrls() 產生 Module Token
  → 附加至模組 URL query string (?token=...)
  → 模組 doGet() 解析 token → sessionVerify()
  → 取得 { email, role, name, 學校設定... }
```

**模組安裝活化流程**：
```
管理員填寫模組試算表連結 + 部署網址
  → installModule() 讀取「模組資訊」工作表驗證
  → 在模組試算表寫入一次性 Nonce
  → server-to-server POST 至模組 deployUrl（page=install）
  → 模組驗證 Nonce 後，將 TOKEN_SECRET 存入自身 Script Properties
  → 回傳 JSON { ok: true }
  → 主系統將模組資訊寫入「模組」工作表
```

## 五、資料流與路由

### 5.1 請求生命週期

```
使用者請求
    │
    ▼
doGet(e) / doPost(e)          ← GAS Web App 入口
    │
    ├─ 載入「設定」工作表（全域設定）
    │
    ├─ [doGet] 依 page 參數路由
    │   ├─ login / 無 page → 登入頁面
    │   ├─ forgot_password → 忘記密碼頁面
    │   ├─ reset_password → 重設密碼頁面（驗證 token）
    │   ├─ student│staff│admin → 驗證 session token → 角色入口頁
    │   ├─ account → 驗證 session → 帳號設定頁
    │   └─ admin_modules → 驗證 admin → 模組管理頁
    │
    └─ [doPost] 依 page 參數路由
        ├─ login → login() → 可能導向 email_otp│totp → 或直接登入
        ├─ email_otp → 驗證 OTP → 建立 session → 角色入口頁
        ├─ totp_verify → 驗證 TOTP → 建立 session → 角色入口頁
        ├─ forgot_password → sendPasswordResetEmail()
        ├─ reset_password → doPasswordReset()
        └─ logout → 返回登入頁
```

### 5.2 前端與後端通訊

- **頁面渲染**：`HtmlService.createTemplateFromFile()` + 樣板變數注入
- **非同步呼叫**：`google.script.run`（GAS 內建）呼叫後端函式（如 `getAccountInfo`、`changePassword`）
- **頁面間跳轉**：標準 `<a>` 連結 + `?page=...&token=...` query string

## 六、認證與安全設計

### 6.1 Token 體系

| Token 類型 | Payload 格式 | 效期 | 用途 |
|-----------|-------------|------|------|
| Session Token | `email\|role\|timestamp` | 2 小時 | 一般頁面存取 |
| 一次性 Token | `email\|timestamp` | 5 分鐘 | OTP / TOTP 驗證流程 |
| 密碼重設 Token | `email\|timestamp` | 30 分鐘 | 忘記密碼重設 |
| Module Token | `JSON {email,role,name,...}` | 2 小時 | 外掛模組身分傳遞 |

所有 Token 格式統一為：`base64url(payload).base64url(HMAC-SHA256)`

### 6.2 密碼儲存

- 格式：`SHA256_salt:SHA256_hex_digest`
- `SHA256_salt` = 36 字元 UUID（去連字號）
- `SHA256_hex_digest` = SHA256(`salt` + `明文密碼`)

### 6.3 兩階段驗證

| 方式 | 實作 | 說明 |
|------|------|------|
| Email OTP | `emailOtpSend()` / `emailOtpVerify()` | 6 位數亂碼，10 分鐘效期，2 分鐘冷卻 |
| TOTP（驗證器 APP） | `totpVerify()` / `totpGenerateSecret()` | RFC 6238，HMAC-SHA1，30 秒間隔，±1 容差 |
| 登入通知 | `sendLoginNotificationEmail()` | 登入時寄送通知信（選擇性） |

### 6.4 其他安全機制

- **Nonce**：一次性 UUID，用於 CSRF 防護（CacheService，10 分鐘效期）
- **TOTP Replay 防護**：CacheService 記錄已使用過的驗證碼（90 秒）
- **Email OTP 冷卻**：CacheService 防止短時間內重複寄送（2 分鐘）
- **Token 簽章**：所有 Token 使用 HMAC-SHA256，金鑰存放於 Script Properties

### 8.1 模組必要條件

1. 模組試算表中須有「**模組資訊**」工作表，包含：
   - 模組名稱、顯示名稱、模組版本、模組作者

2. 模組主程式（`main.js`）須實作 `page=install` 處理安裝活化
3. 模組 `auth.js` 須使用 `generateModuleToken()` / `verifyModuleToken()` 相同演算法
4. 透過 query string `?token=...` 接收主系統傳遞的 Module Token

## 十一、系統初始化流程

1. 將主系統部署為 Web App（任何人存取、以本人身分執行）
2. 在試算表中建立「設定」工作表，填寫必要設定
3. 透過試算表選單設定 `TOKEN_SECRET`
4. （選擇性）設定 Google OAuth 用戶端 ID 與密鑰
5. 建立「學生」、「教職員」、「管理員」工作表（或外部成員名冊試算表）
6. 建立「模組」工作表
7. 部署完成，開始使用

### 完成的架構與功能

#### 前端頁面
- `index.html` 入口：角色選擇（學生/教職員/管理員）、帳號密碼登入、Google OAuth 登入、雙主題切換

#### 後端路由
- `doGet` 路由：`?page=login`（首頁）、`?page=<role>&token=<token>`（角色頁面）
- 所有頁面共用版權宣告（`copyright`）與廣告區（`advertise`），可在設定工作表關閉

#### 認證系統
- 帳密登入 `login()`：比對成員名冊工作表，支援純文字與 `hashPassword()` 加密密碼共存，自動轉換明文為 hash
- Google OAuth 登入 `handleOAuthCallback()`：交換授權碼 → 取得 Email → 比對成員名冊 → 直接渲染角色頁面（不經客戶端跳轉）
- Session 機制 `sessionSign()` / `sessionVerify()`：HMAC-SHA256 簽名，內含 email + role + 2小時過期

#### 金鑰與密碼管理
- 試算表選單「進階功能」→「設定 TOKEN_SECRET」
- 試算表選單「進階功能」→「設定 Google OAuth 用戶端密鑰」
- TOKEN_SECRET 未設定時自動產生（`Utilities.getUuid()`）

#### 資料層
- `getMemberRoster()`：優先讀取設定欄位「成員名冊雲端連結」，無則找同資料夾「成員名冊」試算表
- 成員名冊工作表欄位：電子郵件地址、帳號、密碼、2FA驗證、TOTP密鑰

#### 帳戶管理頁面（account.html）
- 三卡版型：資訊卡（姓名、身分、登入次數、最後登入）、帳密管理卡（可編輯電子郵件、帳號、密碼）、兩階段驗證卡（關閉/電子郵件驗證碼/驗證碼APP）
- 三種身分通用（student / staff / admin），依 session.role 讀取對應工作表
- 帳密儲存含重複檢查（帳號/信箱不可與他人重複）
- 兩階段驗證：選「驗證碼APP」時自動產生 TOTP 密鑰
- nonce 防偽機制保護儲存操作

#### 部署
- `clasp push -f` 強制推送 + `clasp deploy -i <deploymentId> -d <version>` 更新部署

## 附錄 B：開發筆記

### OAuth / 登入認證

#### redirect_uri 有兩種
- 標準（個人帳號）：`https://script.google.com/macros/s/{deploymentId}/exec`
- Workspace（`/a/domain/` 帳號）：`https://script.google.com/a/gms.hlgs.hlc.edu.tw/macros/s/{deploymentId}/exec`
- **Cloud Console 兩種都要註冊**，否則 OAuth 會跳出「要求無效」錯誤
- 實際用哪個 URL = `ScriptApp.getService().getUrl()` 回傳的值

#### appsscript.json 的 `"webapp"` 設定
- `"access": "ANYONE_ANONYMOUS"` 才能讓 Workspace 帳號走正確的 redirect_uri
- `"access": "ANYONE"` 會強制走 `/a/domain/` 路由，導致 redirect_uri 不符

#### 加 `oauthScopes` 後一定要重新授權
- 在 `appsscript.json` 加入 `oauthScopes`（如 `script.external_request`）後
- 部署者的帳號仍保有舊授權，必須在編輯器重新執行任一函式觸發授權對話框
- 否則會出現「你沒有呼叫 UrlFetchApp.fetch 的權限」錯誤

#### OAuth URL 必須在 doGet 伺服器端生成
- 不能在瀏覽器用 `google.script.run` 呼叫產生 OAuth URL
- 要在 `doGet` 裡直接 `ScriptApp.getService().getUrl()` + 建 URL → 存 nonce 到 `CacheService` → 傳到 template
- 不然會遇到 GAS iframe sandbox 限制或 this 上下文錯誤

#### Session 機制
- HMAC-SHA256 簽名，含 email + role + 過期時間（2小時）
- 透過 `CacheService.getScriptCache()` 傳遞 OAuth state (nonce)
- `sessionVerify(token)` 解碼驗證簽名與時效

#### 除錯 OAuth 流程
- 檢查 `CacheService.getScriptCache().get("oauth_state:{nonce}")` 看 state 是否存在
- 檢查部署日誌（GAS 編輯器 → 執行記錄）看 `handleOAuthCallback` 錯誤
- `doGet` 的 `e.parameter.debug` 參數可從 URL 帶入，輔助判斷是哪一步失敗

#### OAuth 回呼後不能做客戶端跳轉（教甄系統寶貴經驗）
- ❌ `handleOAuthCallback` 回傳 `<script>location.href="..."</script>` → 瀏覽器空白頁或拒絕連線
- ✅ 應直接渲染角色頁面回傳：`HtmlService.createTemplateFromFile(role)` 填入 session 後 `.evaluate()`
- 原因：GAS Web App 的 `ScriptApp.getService().getUrl()` 在 Workspace 環境可能回傳非 `/a/domain/` 路徑，客戶端跳轉會跨域被擋
- 教甄系統的做法：登入成功後伺服端直接回傳目標頁面 HTML，不做任何 redirect

### 密碼安全

- 支援純文字與 `hashPassword()` 加密兩種格式同時存在
- 登入成功時，若該帳號仍是明文密碼，自動取代為 hash 值

### 部署流程

```bash
clasp push -f          # 每次都必須加 -f，強制推送本地檔案到雲端
clasp deploy -i <deploymentId> -d <version>
```

- **`-f` 是必須的**：不加 `-f` 會漏推檔案（曾因此延誤三次部署才發現）
- `-i` 指定 deployment ID 更新現有部署，不產生新 URL
- 新版本需手動在編輯器執行任一函式 → 重新授權

### 廣告與第三方嵌入

#### GAS Web App 無法嵌入 Google AdSense

**根本問題一：網域所有權**
- GAS Web App 永遠跑在 `script.google.com` 或 `script.googleusercontent.com`
- AdSense 要求發布商驗證網域所有權，任何人都無法驗證 Google 的網域

**根本問題二：iframe 違反 AdSense 政策**
- AdSense 服務條款明確禁止將廣告放在 iframe 中（[政策說明](https://support.google.com/adsense/answer/3394713)）
- `adsbygoogle.js` 會偵測是否在跨來源 iframe 內，並選擇性拒絕填入廣告
- 這就是 `php-pie.net` 用 iframe 嵌入時，廣告「有時顯示、有時不顯示」的原因

**根本問題三：應用程式的合法途徑不適用 GAS**
- AdSense 提供 WebView API for Ads（Android）/ WKWebView（iOS）讓 App 合法嵌入
- 但需要 Google Mobile Ads SDK，完全不適用 GAS 這種純網頁環境

**目前的實作架構**
```
GAS 頁面 (script.google.com)
  └─ <iframe src="php-pie.net/advertise.php">    ← 跨來源 iframe，違反 AdSense 政策
       └─ adsbygoogle.js                           ← 偵測到 iframe，選擇性拒絕
```

**可行的替代方案**
- 改用不限制 iframe 的廣告服務（如 Carbon Ads、Media.net）
- 或接受 iframe 方式就是不穩定的事實

#### 3.2 handleOAuthCallback (main.js)

```javascript
function handleOAuthCallback(e) {
  if (!nonceVerify(e.parameter.state))           // ← CSRF state 驗證
    return showMessagePage('錯誤', 'state 無效');

  var role = CacheService.getScriptCache().get('oauth_role_' + e.parameter.state);

  // ① 授權碼 → access_token
  var tokenRes = UrlFetchApp.fetch('https://oauth2.googleapis.com/token', {
    method: 'post', muteHttpExceptions: true,
    payload: {
      code: e.parameter.code, client_id: clientId, client_secret: secret,
      redirect_uri: ScriptApp.getService().getUrl(), grant_type: 'authorization_code'
    }
  });
  var tokenData = JSON.parse(tokenRes.getContentText());

  // ② access_token → 使用者 email
  var userRes = UrlFetchApp.fetch('https://www.googleapis.com/oauth2/v2/userinfo', {
    headers: { Authorization: 'Bearer ' + tokenData.access_token },
    muteHttpExceptions: true
  });
  var userInfo = JSON.parse(userRes.getContentText());
  var email = String(userInfo.email || '').trim().toLowerCase();

  // ③ 比對成員名冊 → 簽發 session token → 直接渲染角色頁面（不做客戶端跳轉）
  var token = sessionSign(email, role);
  var tpl = HtmlService.createTemplateFromFile(role);
  tpl.session = { ok: true, email: email, role: role, reason: '' };
  tpl.main = main;
  tpl.execUrl = ScriptApp.getService().getUrl();
  tpl.token = token;
  return tpl.evaluate().setTitle(...);
}
```

### 五、部署與測試

修改程式後部署新版，開啟部署網址測試三種登入方式（帳密登入、登出、Google OAuth 登入）是否正常。

注意：若在 `appsscript.json` 加入新 `oauthScopes`，部署者須在編輯器重新執行任一函式以觸發重新授權。

#### 5.1 手機端 OAuth 帳號選擇器

電腦版 Google OAuth 登入不會重複問要選哪個帳號，**手機版卻每次都跳選擇器**。原因：

- 電腦版 Chrome 有完整 Google session cookie，Google 能自動識別當前帳號
- 手機版瀏覽器（Safari / Chrome PWA / in-app WebView）session context 隔離，Google 無法自動辨識

**解法：`login_hint`** — 每次 OAuth 登入成功後，將 email 存到 `localStorage['gasOAuthHint']`；下次按 Google 登入時，`syncOAuthLink()` 自動從 localStorage 讀取並附加 `&login_hint=<email>`，Google 收到提示後就會略過選擇器或自動選定該帳號。

實作（每個角色頁面 init 區塊加一行）：

```javascript
// student.html / staff.html / admin.html
try { localStorage.setItem('gasOAuthHint', '<?= session.email ?>'); } catch (ex) {}
```

> 若使用者想切換帳號，Google 選擇器仍然可以選其他帳號，`login_hint` 只是「提示」而非「強制」。

### 六、常犯錯誤

| 錯誤 | 現象 | 解法 |
|------|------|------|
| OAuth 按鈕用 `window.location.href` | 跨域錯誤 / 跳轉失敗 | 改用 `<a href>` + `<base target="_top">` |
| redirect_uri 只註冊一種 | Workspace 帳號跳「要求無效」 | Cloud Console 兩種都要註冊（見 §1.1） |
| `appsscript.json` 的 `access` 設 `ANYONE` | Workspace 帳號 URI 跑錯 | 改 `ANYONE_ANONYMOUS` |
| OAuth callback 回傳 `<script>location.href` | 空白頁或拒絕連線 | 直接 `createTemplateFromFile(role).evaluate()` |
| 按登出用 `window.location.href` | 拒絕連線 | 改用 `<form method="post" page=logout>` |
| state nonce 過期（>10分鐘） | 「state 無效」 | 重整頁面 |
| 部署新版但 Cloud Console 沒更新 redirect_uri | OAuth 失效 | 兩邊同步 |
| 加入新 oauthScopes 後沒重新授權 | `UrlFetchApp.fetch` 無權限 | 編輯器執行任一函式重新授權 |
| 手機版 Google OAuth 每次跳帳號選擇器（電腦版不會） | 缺少 `login_hint`，Google 無法自動辨識 | OAuth URL 附加 `&login_hint=<email>`，角色頁 init 將 email 存入 `localStorage['gasOAuthHint']` |
| `clasp push` 忘記 `-f` | 檔案沒被推送 | 加 `-f` 強制推送 |
